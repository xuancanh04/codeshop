# Contributing to CodeHub

First off, thank you for considering contributing to **CodeHub**! 🎉 It's people like you that make CodeHub a great tool.

## Code of Conduct

By participating in this project, you agree to abide by our respectful community standards and treat all contributors with professionalism.

## How Can I Contribute?

### Reporting Bugs
- Ensure the bug was not already reported by searching on GitHub under [Issues](https://github.com/issues).
- If you're unable to find an open issue addressing the problem, open a new one using the **Bug Report** template.
- Include a clear title and description, as much relevant information as possible, and a code sample or an executable test case demonstrating the expected behavior.

### Suggesting Enhancements
- Check if the feature has already been suggested.
- Provide a clear and detailed explanation of the proposed feature and why it would be beneficial to the platform.

### Pull Requests
1. **Fork** the repository and create your branch from `master` or the relevant feature branch.
2. If you've added code that should be tested, add tests or verification steps.
3. Ensure the test suite passes and your code conforms to ESLint guidelines:
   ```bash
   npm run lint
   npm run build
   ```
4. Format your commit messages using the **Conventional Commits** format:
   - `feat:` A new feature
   - `fix:` A bug fix
   - `docs:` Documentation only changes
   - `style:` Changes that do not affect the meaning of the code
   - `refactor:` A code change that neither fixes a bug nor adds a feature
   - `perf:` A code change that improves performance
5. Open a Pull Request with a clear description of changes.

Thank you for your contributions!
